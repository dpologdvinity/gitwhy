# git p4

Use git with a Perforce (p4) project: clone a depot path, pull p4 changes, submit git commits as p4 changelists. Needs the `p4` client and Python.

Fedora: separate `git-p4` package. Not shipped on Debian/Ubuntu.

**Usage:**
`git p4 clone [<sync-options>] [<clone-options>] <p4-depot-path>...`
`git p4 sync [<sync-options>] [<p4-depot-path>...]`
`git p4 rebase`
`git p4 submit [<submit-options>] [<master-branch-name>]`
`git p4 unshelve [--origin=<rev>] <changelist>`

Typical loop: `git p4 clone //depot/path/project`, commit, `git p4 rebase`, `git p4 submit`.

**Depot paths:** `//depot/proj` imports latest state as one commit. `@all` for full history, `@1,6` for changes 1 to 6. Several paths (`//depot/a@all //depot/b@all`) merge into one tree; need the same revision spec and `--destination`. See `p4 help revisions`.

## Flags

All subcommands (`--git-dir` not on `clone`):

| Flag | What it does |
|------|--------------|
| `--git-dir <dir>` | Git folder to use (sets `GIT_DIR`). |
| `-v`, `--verbose` | More progress. |
| `-h`, `--help` | Show subcommand options. |

## Subcommands

| Subcommand | What it does |
|------------|--------------|
| `clone` | New git repo from a depot path. |
| `sync` | Import new p4 changes, or add a depot path. |
| `rebase` | `sync`, then rebase onto the updated p4 branch. |
| `submit` | Send git commits to p4 (or shelve). Alias `commit`. |
| `unshelve` | Shelved changelist to a git commit. |
| `branches` | List p4-import branches and their depot paths. |

### git p4 clone

Creates a folder named after the depot path's last part, imports into `refs/remotes/p4/master`, checks out `master`. Sets `git-p4.useClientSpec` if you used a client spec. Takes every [sync flag](#git-p4-sync) plus:

| Flag | What it does |
|------|--------------|
| `--destination <directory>` | Repo location. Required with several depot paths. |
| `--bare` | Bare repo. |

### git p4 sync

Import new p4 changes into `refs/remotes/p4/master`. With a depot path in a fresh `git init` repo, starts importing there. Uses `refs/remotes/origin/p4/*` first if present (faster). With several branches, sorts changes into them unless `--branch`.

| Flag | What it does |
|------|--------------|
| `--branch <ref>` | Import into this branch. `refs/...` used as is; else becomes `refs/remotes/p4/<ref>`. |
| `--detect-branches` | Make a git branch per p4 branch, via `p4 branch` mappings or `git-p4.branchList`. |
| `--changesfile <file>` | Import exactly the change numbers in this file. |
| `--silent` | No progress. |
| `--detect-labels` | Deprecated: p4 labels on new changes become tags. |
| `--import-labels` | Import p4 labels as tags. |
| `--import-local` | Store branches under `refs/heads/p4/` instead of `refs/remotes/p4/`. Later syncs need it too. |
| `--max-changes <n>` | Import at most `n` changes. |
| `--changes-block-size <n>` | Fetch change list in batches of `n`. Default 500. |
| `--keep-path` | Keep full depot paths in file names (`depot/main/foo.c`). |
| `--use-client-spec` | Pick files by your p4 client's View. Same as `git-p4.useClientSpec`. |
| `-/ <path>` | Skip this depot path. Repeatable. |

### git p4 rebase

**Usage:** `git p4 rebase`

| Flag | What it does |
|------|--------------|
| `--import-labels` | Also import p4 labels. |

### git p4 submit

Submit each current-branch commit not on `p4/master` as its own changelist, then sync and rebase. Needs a p4 workspace (`P4CLIENT` or `git-p4.client`; folder created if missing). Submits as you unless `--preserve-user`. `<master-branch-name>` submits another branch.

Hooks: `p4-pre-submit` and `p4-changelist` can abort (skipped by `--no-verify`); `p4-prepare-changelist` always runs; `p4-post-changelist` runs after success.

| Flag | What it does |
|------|--------------|
| `--origin <commit>` | Submit commits after this. Default: newest p4 commit reachable from `HEAD`. |
| `-M` | Send renames as p4 moves. |
| `--preserve-user` | Submit as each git author. Needs p4 admin. |
| `--export-labels` | Git tags to p4 labels. |
| `-n`, `--dry-run` | Show what would be submitted. |
| `--prepare-p4-only` | Apply the oldest commit to the workspace without submitting; print how to submit or revert. No tag export. |
| `--shelve` | Shelve instead of submit, then revert files. |
| `--update-shelve <changelist>` | Update this shelved changelist. Implies `--shelve`. Repeat in order for several. |
| `--conflict=(ask\|skip\|quit)` | On conflict: ask (default), skip commit, or stop. |
| `--branch <branch>` | Afterward sync this branch instead of `p4/master`. |
| `--commit <sha1>`, `--commit <sha1>..<sha1>` | Submit only this commit or range. |
| `--disable-rebase` | No rebase after. Also `git-p4.disableRebase`. |
| `--disable-p4sync` | No `p4/master` sync after. Implies `--disable-rebase`. Also `git-p4.disableP4Sync`. |
| `--no-verify` | Skip `p4-pre-submit` and `p4-changelist` hooks. |

### git p4 unshelve

**Usage:** `git p4 unshelve [--origin=<rev>] <changelist>`

Creates a commit at `refs/remotes/p4-unshelved/<changelist>` on a parent built from the origin. Renames an existing branch of that name. Refuses if git is behind p4 for those files; `git p4 sync` first.

| Flag | What it does |
|------|--------------|
| `--origin <rev>` | Base for the shelved changes. Default `HEAD`. |

### git p4 branches

**Usage:** `git p4 branches`

Only common flags.
